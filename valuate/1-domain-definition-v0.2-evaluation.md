## 1. 완전성: 8/10

**잘된 점**
- 원문의 Step 0~4, 비기능 요구사항, 필수 사항을 REQ-01~20으로 빠짐없이 뽑았다.
- 분석 생략, 재생성, 주입 결과 보고, 구독 소멸 규칙이 추가됐다.
- 결정 로그(D), 리스크 레지스터(R), KPI를 각각 분리했다.

**결함**
- **Step 4가 실제로 끝나지 않는다.** BR-30은 "Tailwind 클래스로 스타일링한 단일 HTML"만 규정한다. WING 상세설명에 Tailwind 스타일시트가 로드되지 않으면 클래스 기반 HTML은 스타일이 깨진다. 인라인 CSS로 변환하는 규칙도, 관련 리스크도 없다. 쿠팡 쪽 동작은 확인이 필요하다.
- **최종 HTML의 이미지가 만료된다.** BR-52는 최종 HTML에 원본 이미지 서명 URL을 넣는다. URL이 만료되면 실제 상품 페이지 이미지가 깨진다. D-12는 미결이고 R-7은 "확인 필요"로만 적혀 있어, 핵심 흐름이 미결 결정에 막혀 있다.
- **원가 상한에 구멍이 있다.** 자격 조건은 "잔액 1 이상"(BR-10)뿐이고 상한은 모두 프로젝트 단위다(BR-34, 41, 45). 크레딧 1개로 프로젝트를 무제한 만들고, 각각 생성 1회, 재생성 3회, AI 수정 성공 3회·실패 6회를 무료로 쓸 수 있다. 분석 재시도는 상한이 아예 없다. R-6 대응책도 프로젝트 단위뿐이다.
- **빠진 영역**
  - 개인정보와 데이터 보존·삭제(프로젝트·이미지 삭제, 회원 탈퇴)
  - Kakao에서 이메일을 받지 못하는 경우(BR-02는 이메일이 있다고 전제)
  - 무료 Gemini API로 셀러의 미출시 상품 정보·이미지를 보낼 때의 데이터 활용 약관 리스크
  - Vercel 함수 실행 시간 제한과 BR-37(p90 60초)의 관계
  - 플랜 변경, 프로젝트 폐기 상태
- **모델 지원 종료 가능성.** Gemini 1.5 Flash와 Claude 3.5 계열은 이미 지원이 종료됐을 가능성이 높다(확인 필요). 그런데 D-10은 여전히 "가정 / 상용 전환 전"이다.

**개선 제안**
- 최종 HTML 출력 규칙(인라인 CSS, 영구 이미지 호스팅)을 BR로 추가하고, D-12를 착수 전 블로커로 올린다.
- 계정 단위 LLM 호출 상한과 분석 재시도 상한을 둔다.

## 2. 명확성: 7/10

**잘된 점**
- 자격 규칙을 BR-10 하나로 통일했다.
- 멱등성을 원장 유니크 제약 하나로 정리했다.
- 워터마크 보호 범위를 BR-53과 R-1로 명시해, v0.1의 모순은 형식상 풀렸다.

**v0.2에서 새로 생긴 모순**
1. **Middleware 잔액 검사와 BR-10 예외가 충돌한다.** 7장 MW의 "잔액 자격 확인"과 6장 "MW→API: 세션·잔액 1 이상 확인"은 모든 `/api/*`에서 잔액을 본다고 읽힌다. 그러나 BR-10은 PUBLISHED 조회·재주입을 잔액과 무관하게 허용한다. 잔액 1인 사용자가 퍼블리시하면 잔액이 0이 되고, `/api/publish/token` 발급이 막혀 첫 주입조차 못 할 수 있다.
2. **ANALYZED 진입 조건이 세 곳에서 다르다.** 다이어그램은 "분석 성공 + USP 선택", 전이 표는 "크롤링·LIGHT 분석 성공", 이벤트 표는 "USP 추출 완료"다. selectedUsps도 AnalysisResult와 Project 양쪽에 중복 정의돼 있고, USP 선택을 저장하는 API가 없다.
3. **구독 상태 정의가 어긋난다.** Subscription 상태값의 CANCELED·PAST_DUE를 어느 규칙도 쓰지 않는다. BR-17은 해지하면 곧바로 ENDED로 바꾸는 것처럼 읽히지만, 8장 SubscriptionEnded는 "periodEnd가 지난 뒤" ENDED로 바꾼다.
4. **Wallet 생성 시점이 어긋난다.** 8장에서는 Credentials 가입자의 UserSignedUp이 이메일 인증 후에 발생하고 그때 Wallet이 생긴다. 6장과 AC-BR01은 가입 즉시 User와 Wallet을 만든다.
5. **"자격은 하나다"와 BR-04가 맞지 않는다.** BR-04가 이메일 인증이라는 조건을 하나 더 붙인다.
6. **출처 태그가 정확하지 않다.** BR-51 [원문]에 "2중 구성은 [가정]"이 섞여 있다. BR-52의 서명 URL, BR-72의 "Anthropic일 때만"(원문은 "고려"), BR-12·BR-41의 메커니즘 세부는 원문에 없는데 [원문]으로 표시됐다. BR-17은 [파생]인데 가정이 들어 있다.
7. **범위 선언과 내용이 모순된다.** 문서 첫머리에서 "구현 세부 사항은 다루지 않는다"고 선언했지만 CHECK 제약, 조건부 UPDATE, `data-block-id`, 390px, 토큰 10분이 본문에 있다.
8. **워터마크 보호의 논리가 약하다.** 보호 대상인 원본 이미지는 사용자가 직접 올린 파일이라 사용자가 이미 갖고 있다. 블록 반복 워터마크도 DOM 속 CSS 배경이라 오버레이처럼 지울 수 있다. 마크업을 복사하고 워터마크를 지운 뒤 이미지를 자기 원본으로 바꾸면 결제 없이 완성본을 얻는다. 실제로 지켜야 할 자산인 AI 생성 문구와 레이아웃은 R-1에서 "수용"으로 처리됐고, 영향은 "중"으로만 매겨졌다.

**개선 제안**
- 자격 검사 위치를 한 곳으로 정한다(Middleware는 인증만, 잔액 검사는 API별 목록으로).
- 상태 전이, 이벤트, 엔티티 정의를 한 원천에서 관리한다.
- 보호 목표를 다시 정의하고 R-1의 영향을 재평가한다.

## 3. 추적성: 8/10

**잘된 점**
- BR 50개를 모두 대조했고, 4.2 매트릭스에서 빠진 BR은 없다.
- 매트릭스의 API는 모두 7장에 있고, 이벤트는 매트릭스와 8장이 서로 일치한다.
- 존재하지 않는 BR·D·R·KPI ID를 가리키는 참조는 없다.

**결함**
- **자체 표기 규약 위반.** 규약은 "장 번호가 아니라 ID로 참조"인데 REQ-13·14는 "7장 원칙 1", REQ-20은 "5~8장", D-26은 "11장"을 참조한다. REQ-13(1인 개발, 데스크톱, Vercel)이 가리키는 원칙 1은 렌더링 분리에 관한 것이라 관련이 없다. 파이프라인 원칙에는 ID가 없다.
- **연결이 약한 매핑.** REQ-16 "서버리스 DB"를 BR-14(음수 CHECK)로 추적한다. REQ-19 "고마진"의 AC-BR73은 로그 건수만 센다. REQ-20의 AC는 "문서 리뷰"다.
- **역방향 공백**
  - `/api/billing/checkout`을 규정하는 BR이 없다.
  - 재생성 API가 따로 없어 `/api/generate`와 어떻게 구분하는지 알 수 없다.
  - BR-52의 "최종 HTML·서명 URL 요청"과 BR-10의 "PUBLISHED 조회"에 해당하는 API가 없다.
  - BR-65의 원격 셀렉터 설정을 제공하는 곳이 7장에 없다.
- **AC 범위 표기.** "AC-BR11~15"처럼 범위로 적어 개별 AC가 있는지 매트릭스만으로 확인하기 어렵다.

## 4. 검증 가능성: 7/10

**잘된 점**
- 모든 BR에 Given/When/Then 형식의 AC가 있다.
- 동시성 AC(AC-BR13, AC-BR41)와 롤백 AC(AC-BR12)가 구체적이다.

**형식만 갖췄거나 테스트할 수 없는 AC**
- **AC-BR74**: 종료 조건 "모든 AC 통과"에 자기 자신이 포함돼 순환한다. AC-BR70·72는 Claude로 전환한 뒤에만 통과할 수 있어 Gemini 단계에서는 통과가 불가능하다. E2E 시나리오에 실제 WING 주입도 들어 있다.
- **AC-BR72**: 캐시가 동작하는 조건(최소 프롬프트 길이, TTL 안의 연속 호출)이 빠져 결과가 비결정적이다.
- **AC-BR53**: "그대로 게시할 수 없음"은 주관적 판단이다.
- **AC-BR44**: "HTML 전체 payload"를 판별하는 기준이 없다.
- **AC-BR22·AC-BR32**: 검사 방법과 범위가 정의되지 않았다.
- **AC-BR63·AC-BR71**: 스캔할 비밀값 패턴이 정의되지 않았다.
- **AC-BR70**: 변경 0줄이어야 하는 "도메인 코드"의 경계가 없다.
- **AC-BR37**: 운영 7일치 로그가 필요해 출시 전에는 검증할 수 없다.
- **AC-BR15**: "임의 시점"은 매 TX 뒤 불변식 검사로 바꿔야 한다.
- **AC-BR41**: 동시성 테스트에서 "1건 성공"이 되려면 LLM을 목(mock)으로 대체한다는 전제가 필요하다.

**AC 없이 남은 절**
- BR-02 미검증 이메일 분기, BR-10 PUBLISHED 조회 예외, BR-16 구독 크레딧부터 차감하는 순서
- BR-17 ENDED 전이·Cron·EXPIRE와 GRANT의 동일 TX 처리
- BR-34·BR-41 실패 시 카운트 복원·수동 편집 초기화, BR-45 aiEditFailCount 증가
- BR-60 토큰으로 다른 API 호출 시 거절, BR-81 robots Disallow, BR-30 Tailwind 사용 여부
- BR-20 정상 URL·쿼리스트링이 붙은 URL

**남은 동시성 공백**
- 선점한 카운트를 복원하기 전에 서버리스 함수가 타임아웃되면 카운트가 영구히 새어 나간다.
- aiEditFailCount 확인이 원자적이지 않아 6회를 넘을 수 있다.
- 최초 생성에 중복 실행 방지가 없다.
- 재생성·AI 수정이 진행 중일 때 퍼블리시가 커밋되는 경합이 있고, Project에 버전(낙관적 잠금)이 없다.

## 5. 유지보수성: 8/10

**잘된 점**
- 변경 이력은 추가만 하는 방식이다.
- BR은 컨텍스트별 10단위로 번호를 매기고, ID는 삭제·재사용하지 않는 규약이 있다.
- D·R·KPI가 분리됐고, [가정] 규칙에는 모두 D-ID가 붙어 있다.

**결함**
- **중복이 많아 불일치 위험이 크다.** "3회"는 용어집, BR-34, BR-41, 5장, 8장, D-5, R-6에 반복된다. p90 60초는 BR-37, D-17, KPI-7에 있다. 보호 방식은 BR-32, BR-50~53, D-21, R-1에 흩어져 있다. BR-33은 BR-11과 사실상 같다. 2절의 모순 1~4가 바로 이 중복에서 생겼다.
- **변경 이력.** 바뀐 BR·D ID 목록이 없어 버전 간 diff를 추적할 수 없다.
- **결정 로그.** D 26개가 모두 같은 담당자이고 기한은 마일스톤 표현이다. D-4는 환불이 미정인데 상태가 "가정"이다. 블로커 결정(D-2, D-12, D-23)의 우선순위 표시가 없다.
- **리스크 레지스터.** 담당, 트리거, 상태, 재평가 시점 열이 없다.
- **KPI 정의**
  - KPI-4는 퍼블리시하지 않은 프로젝트의 LLM 원가(KPI-3 기준 약 70%)를 빼서 마진이 부풀려진다.
  - KPI-5는 injectStatus가 마지막 값으로 덮어써져 시도 단위 성공률을 계산할 수 없다.
  - KPI-2는 이벤트 저장처가 정의되지 않았고, KPI-6은 유입 경로 필드가 없다.
- **문서 크기.** 564줄에 구현 메커니즘이 BR 본문에 섞여 있어, 정책을 바꿀 때 여러 절을 동시에 고쳐야 한다.

## 범위 초과 판단

부분적으로 초과했다. 원문이 스택 간 파이프라인도 요구하므로 API 경로와 아키텍처는 정당하다. 반면 DB CHECK 제약, 조건부 UPDATE 식, `data-block-id`, 390px, 토큰 10분, 일 1회 Cron, 원장 유니크 제약 WHERE 절은 설계 문서 수준이다.

권고:
- BR에는 "무엇을 보장하는가"만 남긴다.
- 메커니즘은 AC나 별도 기술 설계서로 옮긴다.

## 남은 개선 과제 Top 5

1. **최종 HTML을 게시할 수 있게 확정한다.**
   - WING 호환 출력 규칙(인라인 CSS, script·link 금지)을 BR로 추가한다.
   - 영구 이미지 호스팅을 정해 D-12·R-7을 착수 전에 종결한다.
   - 모델 지원 종료 여부(D-10)를 즉시 확인한다.
2. **원가 방어를 계정 단위로 확장한다.**
   - 계정·기간별 생성·분석 호출 상한과 분석 재시도 상한을 둔다.
   - KPI-4에 퍼블리시하지 않은 프로젝트의 원가를 포함하고, R-6을 갱신한다.
3. **정의 모순을 없앤다.**
   - Middleware는 인증만 맡고, 잔액 검사 대상 API를 목록으로 명시한다.
   - ANALYZED 조건과 selectedUsps의 소유 위치를 하나로 정한다.
   - Subscription 상태 전이와 Wallet 생성 시점을 정의한다.
4. **AC를 보강하고 동시성 공백을 메운다.**
   - 절이 여러 개인 BR은 절마다 AC를 둔다.
   - AC-BR74의 순환을 없앤다(Gemini 단계와 Claude 단계의 AC 집합을 분리).
   - 선점 누수 복구, 실패 카운트 원자화, Project 버전(낙관적 잠금), 생성 중복 방지를 추가한다.
5. **보호 목표를 다시 정하고 문서를 줄인다.**
   - 보호 자산을 AI 생성 문구와 레이아웃으로 재정의하고 R-1을 재평가한다.
   - 구현 메커니즘은 설계서로 옮기고, 출처 태그를 다시 분류한다.
   - 변경 이력에 바뀐 ID 목록을 기록한다.
